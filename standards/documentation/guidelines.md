# Documentation

Documenter ce qui aide à décider, utiliser, exploiter ou modifier le système.

- Le `README.md` explique objectif, démarrage, commandes et pointeurs vers les détails.
- Les décisions structurantes et leurs compromis sont tracés dans des ADR courts lorsque nécessaire.
- Les contrats publics, procédures d'exploitation et scénarios de récupération restent proches du code concerné.
- Les commentaires expliquent le pourquoi non évident, pas la syntaxe.
- Toute modification qui invalide une documentation la met à jour dans la même pull request.
- Éviter la duplication : choisir une source de vérité et créer des liens.

Les instructions destinées aux agents restent concises ; les workflows détaillés appartiennent aux skills ou aux documents ciblés.
